# Workout Lab 100 v2

Phone captures miles. Desktop does not record GPS. Both share one local ledger. No server, no accounts.

## Ledger event

Ingest writes one workout `PointEvent`:

- `id` is `trk_<sessionId>`
- `source` is `tracker`
- `points` is `floor(miles / rules.milesPerPoint)` — 1.25 mi at 0.25 mi/pt is 5
- `exerciseId` is the session value, otherwise `on-foot`
- `categoryId` is the session value, otherwise `cardio`

The same `sessionId`, or an event id `trk_<sessionId>`, is a duplicate and is left unchanged. Under 1 point is not added.

Export version stays 1. The storage key stays `workout-lab-100.v1`. The packer leaves tracker-backed events in `events` (the unpack rest list). It does not fold them into `eventPack`.

## Import

Settings → **Import JSON** still merges a lab pack (`profiles` or `profile`). Anything else is ingested as walk session(s).

**Import sessions** reads one or more JSON files and totals them in one note. A file that is not JSON counts as “1 file unreadable”.

Accepted shapes:

- one `session.v2` object
- the phone export below (ISO `startedAt` / `stoppedAt`, or epoch `startedAtMs` / `endedAtMs`)
- an array of those objects
- `{ "sessions": [ ... ] }`
- a lab export whose profile carries `sessions`

`sessionId` comes from `sessionId` or `id` (string or number). Miles come from `miles`, `distanceMiles`, or `workoutDistanceMeters / 1609.344`. A phone `points[]` track is mapped to `path` (`acc` meters × 3.28084 = `accFt`, `time` ISO or epoch = `t`).

## Phone JSON

`SessionExporter.toJson` keeps the old keys and adds the ledger fields. The share picker and the on-device archive both write this shape. GPX is unchanged.

- `app`: `workout-lab-100`
- `type`: `workout_session`
- `schema`: `session.v2`
- `sessionId` and `id`: `SessionEntity.id` as a string
- `startedAt` / `stoppedAt`: ISO-8601 (the old keys; `stoppedAt` is null when the session has no stop time)
- `startedAtMs` / `endedAtMs` / `endedAt`: epoch milliseconds (`endedAt` is the stop time, or the start time when stop is missing)
- `miles`: `workoutDistanceMeters / 1609.344`
- `workoutDistanceMeters`: unchanged
- `exerciseId`: `on-foot`
- `categoryId`: `cardio`
- `finishReason`: session status (`complete`, `recording`, or `paused`)
- `path`: `{ "t", "lat", "lon", "accFt" }` from each saved point
- `points`: the original track array (`lat`, `lon`, `ele`, `time`, `acc`, `speed`)

Desktop recomputes points from miles and the profile rule. It does not trust a numeric `points` field when the phone file uses `points` for the track.

## Phone ledger

The phone has a **Ledger** tab next to Current and Recent.

- Today shows `towardCap / cap`, incoming overflow when it is above 0, on-foot miles for tracker workouts that day, and workout points that day.
- Scoring matches the desktop: local calendar days, `incoming` is the previous day's overflow when overflow is on, `towardCap = min(cap, rawWorkout + incoming)`, `overflowOut = max(0, rawWorkout + incoming - cap)`.
- Add logs a manual workout (`source: manual`, id `evt_<uuid>`) against an exercise. On foot is seeded. A point value of 0 is refused.
- Recent lists the newest events. Tracker rows show miles and points. Manual rows show the exercise name and points.
- The snapshot is `filesDir/lab/lab.json` (app-private). It is a version-1 lab export. GPS points stay in Room.
- When a walk finishes, the phone upserts `trk_<sessionId>` if `floor(miles / milesPerPoint)` is at least 1. Opening the Ledger tab reconciles finished Room sessions the same way. The same id or session id is a no-op.
- **Import lab JSON** reads a desktop export (`profiles` or `profile`). Rules come from the active profile, or `public`, or the first profile. Exercises merge by id. Events merge by id and skip duplicates. Local `trk_*` events that the file does not contain stay. Packed desktop `eventPack` rows are unpacked. Plans are stored and not shown.
- **Export lab JSON** writes `{ version: 1, exportedAt, activeProfileId, profiles: [...] }` with flat `events`, which desktop Import JSON already accepts.

## Desktop Today

Today lists the local day's events, newest first. A tracker row is the exercise name, miles, and points (`On foot · 1.25 mi · 5 pts`). A manual row is the exercise name and points. Work and reward rows show that kind when they exist. The miles line is the sum of `event.miles` for tracker events, and for any event that already has miles above 0. It stays hidden at 0. The cap bar is unchanged: those walk points are already inside `towardCap`. The header score line appends `· 1.25 mi` when that sum is above 0. Totals stays a point stack.
